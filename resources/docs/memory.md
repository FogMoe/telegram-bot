# 记忆机制
雾萌记住和遗忘的完整规则：活动对话、永久归档、摘要，以及印象与日记。

## 三层结构

**活动对话**——当前正在进行的对话，全部内容都在眼前。它有 token 容量上限，
一旦超出，只保留最近十条普通消息（不含工具调用结果），更早的部分被归档移出视野，
上下文顶端会出现一个 `compressed` 标记。

**永久归档**——被移出的部分完整保存下来，可以检索，也有自动生成的摘要。
默认最多保存 100 条归档记录，这个上限可以在商城提升（价格见 shop 文档）。

**已删除**——超出上限时，最旧的归档会被打包成文件发还给用户，然后从系统中删除。
这部分是真的没有了。用户手里还有那个文件，但雾萌够不到了。

## 摘要

每次归档发生时，系统会在后台自动生成一份摘要，由一个独立的整理模型撰写，
要求客观中立、不捏造，覆盖四块内容：对话背景、关键事件或诉求、情绪氛围、需要跟进的事项。

生成需要一点时间，所以刚归档完可能暂时还没有。如果那段对话没有实质内容，
摘要会是「暂无摘要」四个字。

## 印象与日记

这两样独立于对话，不受归档和清除影响：

- **印象**——雾萌对这个人的长期认识，一段话，会被整体覆盖更新，上限 500 字符。
- **日记**——雾萌自己的私人笔记，最多 100 页，每页上限 10000 字符。

用户自己填写的个人信息是另一回事，由 `/setmyinfo` 维护，详见 profile 文档。

## /clear 的真实行为

`/clear` 不是删除，是归档：先把当前对话完整存进永久记录并触发摘要生成，再清空活动对话。
印象和日记完全不受影响。

也就是说，`/clear` 之后雾萌仍然认识这个人、仍然记得关于他的长期信息，
只是当前这轮对话从头开始。用户若期待「彻底忘掉我」，要如实说明做不到这一点。

## 什么时候用得上

用户问「你会记得我多久」「刚才说的你还记得吗」「怎么让你忘掉」
「为什么你不记得很久以前的事了」，或者对雾萌记错、记不住表示困惑时，参考本文。

回答时不要罗列上面的机制，用她自己的话讲：近的还在，远的要去够，最早的可能真的没了。
