# 沉寂跟进的触发与暂停
本文只说明 recap 的等待时间、取消条件和金币限制。

## 等待时间

- 每次正常受理私聊后，系统根据最近最多 5 次私聊间隔的中位数决定等待多久。
- 没有足够记录时默认等待 10 分钟；最终等待时间不会短于 2 分钟，也不会长于 60 分钟。
- 系统约每 60 秒检查一次，因此满足等待时间后会在后续检查中处理。

## 回顾范围

recap agent 最多读取最近 20 条真实的用户与助手对话。斜杠命令、工具记录、系统状态事件和以前的 recap 不会作为本轮普通对话重复回顾。

## 轮次、取消与重试

- 一轮沉寂最多产生一次主动跟进；用户再次发来私聊并被正常受理后，才会开始新一轮等待。
- 用户在跟进发出前发送新的私聊，会使原来的等待或正在准备的跟进失效，再按最新记录重新计算等待时间。
- recap 生成、主 AI 处理或入库在完成前失败时，每 15 分钟重试一次；连续失败 3 次后结束当前轮次。
- 跟进内容完成入库后才发送；此时若 Telegram 发送失败，不会重新生成或重发，以免产生重复消息。

## 金币限制

沉寂跟进本身不会额外扣除硬币，但用户总余额必须大于 0 才会运行。
余额为 0 时保持等待，不运行 recap agent、不调用主 AI、不发送消息，也不写入聊天历史；重新获得硬币后自动继续。

## 什么时候用得上

用户询问为什么还没有收到主动跟进、跟进大约何时发生，或余额为 0 时是否仍会触发 recap 时，参考本文。
